# C89 uxn/Varvara Emulator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Our own uxn/Varvara emulator: a portable freestanding C89 CPU core, a C89 Varvara device layer, and an SDL3 + cimgui desktop host that runs Left, all built offline with nob.h.

**Architecture:** Three layers under `emu/`. `core/` is the CPU with no headers and no state outside a host-owned struct. `varvara/` adds the devices with libc. `host/` is the SDL3 window and the cimgui debugger. A headless CLI (`cli/`) runs the same core and devices for tests, and is checked byte for byte against the vendored reference emulator uxnmin.

**Tech Stack:** C89 (core, varvara, cli, debug), C99 (host), C++ (Dear ImGui via cimgui), clang 22 (x86_64-pc-windows-msvc), tcc 0.9.27, nob.h, SDL3 release-3.4.20 (built with its own CMake + Ninja), cimgui master @ 2a6a93f.

**Spec:** `docs/superpowers/specs/2026-11-08-c89-emu-design.md`

## Global Constraints

- Everything lives under `emu/`. Commit directly to `master`; no branches.
- Core: ISO C89, freestanding, **no `#include` at all**, no libc calls, no globals or `static` mutable data, no `//`, no `long long`, no `inline`, no VLAs, no floats, no mixed declarations. Never assume `int` > 16 bits, `unsigned char` == 8 bits or `unsigned short` == 16 bits: mask with `& 0xff` / `& 0xffff`. Shorts are built from bytes, big-endian. No type punning.
- Core types are `ux_u8` and `ux_u16`, not `Uint8` (SDL uses that name).
- Varvara, cli and debug code: C89 plus libc, no SDL.
- Host: C99 is allowed. Dear ImGui is C++, compiled with clang++. Our host code is C and reaches imgui only through cimgui.
- The build needs only clang/clang++, tcc, CMake + Ninja (SDL3 only) and the repo. No network, including for tests.
- CMake is only for SDL3. Everything else builds through `emu/nob.c`.
- Behaviour follows the current uxn and Varvara spec. **Where the wiki and the reference (uxnmin, uxn11) disagree, the reference wins.**
- Vendored code keeps its upstream LICENSE plus a `VERSION` file with the upstream URL and commit or tag.
- Never copy from uxn32's `uxn32.c` ("all rights reserved").
- Debugger toggle: **Right Ctrl**, which never reaches the ROM. Only Left Ctrl is Controller button A. No function keys, Insert, Page Up/Down, End or arrow keys for any emulator shortcut.
- Build outputs go in `emu/build/`; the repo `.gitignore` already ignores `build/`.

## Review Focus

1. **Windows text-mode stdio.** ROM bytes piped through stdin/stdout, and console bytes 0x0a/0x0d/0x1a, must round-trip unchanged. Test in Task 3: `console_binary_roundtrip`.
2. **Bad ROM files.** A missing, empty or over-size ROM (more than 0xff00 bytes) gets a one-line error and a nonzero exit, with no crash and no partial run. Test in Task 3: `cli_rejects_bad_roms`.
3. **Awkward file names in Left's browser.** Spaces, UTF-8 names, `..` at a drive root, and directories with more entries than fit in the listing buffer. Expected: listings are correct and truncated cleanly. Test in Task 4: `file_listing_edge_cases`.
4. **Hostile screen sizes.** A ROM setting width or height to 0 or 0xffff. Expected: the size is clamped (1..1024 × 1..1024, my call), with no crash and no huge allocation. Test in Task 5: `screen_resize_clamped`.
5. **Stuck modifiers.** Toggling the debugger with Right Ctrl, or losing window focus while keys are held, must not leave a Controller button stuck down in the ROM. Test in Task 7: `keymap_release_on_focus_loss`.

### Task 2: The CPU core

**Files:**
- Create: `emu/core/uxn.h`, `emu/core/uxn.c`, `emu/tests/core_test.c`
- Modify: `emu/nob.c` (targets `check-core`, `test`)

**Interfaces:**
- Produces, exactly as the spec defines them: `ux_u8`, `ux_u16`, `UxStack { ux_u8 dat[256]; ux_u8 ptr; }`, `Uxn { ux_u8 *ram; UxStack wst, rst; ux_u8 dev[256]; ux_u8 (*dei)(struct Uxn *, ux_u8 port); void (*deo)(struct Uxn *, ux_u8 port); void *user; ux_u16 pc; ux_u8 fault; }`.
  - `#define UXN_BRK 0`, `UXN_LIMIT 1`, `UXN_FAULT 2`.
  - `int uxn_eval(Uxn *u, ux_u16 pc, unsigned long max_steps);`
  - Overridable macros `UXN_PEEK(u,a)`, `UXN_POKE(u,a,v)`, `UXN_DIV(a,b)`, each wrapped in `#ifndef`.
  - The host zeroes the struct (there is no init function), sets `ram`, `dei`, `deo` and `user`, and loads the ROM at 0x0100.
- Device-call semantics (pinned from uxnmin): **DEI** sets `x = dei(u, port)`. **DEI2** does that, then reads the second byte raw from `dev[(port+1)&0xff]` with no callback. **DEO** stores `dev[port]=v`, then calls `deo(u, port)`. **DEO2** stores the high byte in `dev[port]` with no callback, then stores the low byte in `dev[port+1]` and calls `deo(u, port+1)`. After every `deo` or `dei` call, if `u->fault` is nonzero, eval returns `UXN_FAULT`, with `u->pc` set to the next instruction.
- Opcodes: `00 BRK, 01 INC, 02 POP, 03 NIP, 04 SWP, 05 ROT, 06 DUP, 07 OVR, 08 EQU, 09 NEQ, 0a GTH, 0b LTH, 0c JMP, 0d JCN, 0e JSR, 0f STH, 10 LDZ, 11 STZ, 12 LDR, 13 STR, 14 LDA, 15 STA, 16 DEI, 17 DEO, 18 ADD, 19 SUB, 1a MUL, 1b DIV, 1c AND, 1d ORA, 1e EOR, 1f SFT`. Mode bits are `0x20` short, `0x40` return, `0x80` keep. The special cases are `20 JCI, 40 JMI, 60 JSI, 80 LIT, a0 LIT2, c0 LITr, e0 LIT2r`. JCI, JMI and JSI take a signed 16-bit offset relative to the address after their 3 bytes. Comparisons push one byte even in short mode. SFT shifts right by the low nibble, then left by the high nibble. DIV by zero gives 0.

- [ ] **Step 1: Write `tests/core_test.c`.** It's C89 with libc and a minimal `CHECK(cond)` macro that counts failures and prints `file:line`. A helper `run(const ux_u8 *code, int n, unsigned long max)` zeroes a static `Uxn` and 64K RAM, copies `code` to 0x0100, records every `deo` port in a log, and returns `uxn_eval(u, 0x0100, max)`. Tests are listed as bytes → expected working stack (bottom first):
  - `lit_add`: `80 02 80 03 18 00` → `05`
  - `dup_is_06`: `80 07 06 00` → `07 07`
  - `nip_is_03`: `80 01 80 02 03 00` → `02`
  - `add_keep`: `80 02 80 03 98 00` → `02 03 05`
  - `add2_wraps`: `a0 ff ff a0 00 02 38 00` → `00 01`
  - `pop_empty_wraps`: `02 00` → `wst.ptr == 0xff`
  - `div_by_zero`: `80 05 80 00 1b 00` → `00`
  - `sft_left`: `80 01 80 10 1f 00` → `02`; `sft_both`: `80 34 80 33 1f 00` → `30`
  - `gth`: `80 05 80 03 0a 00` → `01`; `equ2_one_byte`: `a0 12 34 a0 12 34 28 00` → `01`
  - `jci_taken`: `80 01 20 00 01 00 80 aa 00` → `aa`; `jci_not_taken`: `80 00 20 00 01 00 80 aa 00` → empty
  - `jsi_pushes_return`: `60 00 01 00 00` → `rst` = `01 03`
  - `stz_ldz`: `80 42 80 10 11 80 10 10 00` → `42`, and `ram[0x10] == 0x42`
  - `deo2_one_callback`: `a0 12 34 80 18 37 00` → deo log = `{0x19}`, `dev[0x18]==0x12`, `dev[0x19]==0x34`
  - `step_limit`: `40 ff fd` (JMI to itself) with `max=1000` → returns `UXN_LIMIT`, `pc == 0x0100`
  - `host_fault`: a deo callback that sets `u->fault = 1`, on `80 01 80 0f 17 80 99 00` → returns `UXN_FAULT`, and the stack doesn't contain `99`
  - `pc_wraps`: `ram[0xffff] = 0x01` (INC) with stack `05`, then eval at 0xffff → it executes INC, wraps to 0x0000 and runs the `00` BRK there → `06`
- [ ] **Step 2: Run** `./nob.exe test`. Expected: it fails to compile because `core/uxn.h` doesn't exist yet.
- [ ] **Step 3: Implement `core/uxn.h` and `core/uxn.c`** as specified. Use a `switch` on the full opcode byte or on the base opcode, your choice. Nothing in the core may need an init loop, so the compiler never emits a `memset`.
- [ ] **Step 4: Add `check-core` to nob.**
  - `clang -std=c89 -pedantic -Wall -Wextra -Werror -ffreestanding -fno-builtin -O2 -c core/uxn.c`, and the same at `-O0`.
  - `tcc -c core/uxn.c`.

- [ ] **Step 5: Run** `./nob.exe check-core && ./nob.exe test`. Expected: `check-core` prints nothing and exits 0, and `test` prints `core: 19 passed, 0 failed`.

### Task 8: Disassembler, debug session and cimgui debugger

**Files:**
- Create: `emu/debug/disasm.h`, `disasm.c`, `emu/debug/session.h`, `session.c`, `emu/host/debugger.c`, `emu/tests/debug_test.c`
- Modify: `host/main.c`, `nob.c`

**Interfaces:**
- Produces:
  ```c
  /* disasm.h: returns instruction length 1..3; writes NUL-terminated text */
  int uxn_disasm(const ux_u8 *ram, ux_u16 addr, char *out, int outlen);
  /* session.h */
  typedef struct DebugSession { int paused; ux_u8 bp[0x10000 / 8]; } DebugSession;
  void dbg_toggle_breakpoint(DebugSession *s, ux_u16 addr);
  int  dbg_has_breakpoint(const DebugSession *s, ux_u16 addr);
  int  dbg_step(DebugSession *s, Varvara *v);       /* one instruction */
  int  dbg_step_over(DebugSession *s, Varvara *v);  /* JSR/JSR2/JSI: run until return */
  int  dbg_continue(DebugSession *s, Varvara *v, unsigned long max_steps); /* stops at bp */
  ```
  All of these return a `UXN_*` code. In `dbg_continue`, stopping at a breakpoint returns `UXN_LIMIT` with `s->paused = 1`.
- Disassembly format: the mnemonic with `2`, `k`, `r` suffixes in that order (`ADD2kr`). `LIT 12`, `LIT2 1234`. JCI, JMI and JSI show the absolute target (`JSI 0104`). BRK is `BRK`.
- Step over: if the instruction at `pc` is `JSR`, `JSR2` or `JSI` (any mode), keep single-stepping until `pc` equals the address after it and `rst.ptr` is back to its value before the call, or BRK or a fault. Otherwise it's the same as `dbg_step`.
- While paused, no vectors run and input events are dropped *(my call)*. Reset reloads the ROM and boots again.
- Panels (`debugger.c`), per the spec:
  - CPU: PC, both stacks, and pause / step / step over / continue / reset buttons.
  - Disassembly around PC; clicking a line toggles a breakpoint.
  - Memory: hex view of RAM and of the device ports, labelled with `varvara_port_name`.
  - Console: the captured `on_console` output.
  - Menu bar: Open ROM, Reload, Zoom.

  Right Ctrl shows or hides all of it. Debugger shortcuts act only while an imgui window has focus and avoid the banned keys.

  - `step_over_jsi`: for code `60 00 01 00 80 07 6c` at 0x0100 (JSI to 0x0104, which pushes 07 and returns with `JMP2r`), `dbg_step_over` lands with `pc == 0x0103` and the working stack holding `07`.
  - `breakpoint_stops`: with a breakpoint at 0x0102 in `80 01 80 02 18 00`, `dbg_continue` stops with `pc == 0x0102`.
